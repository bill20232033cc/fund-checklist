## Findings

### 1-未修复-高-exception 吞没导致持仓抽取错误被静默转换为"无数据"

- **入口/函数**: `FundReadingService._extract_holdings_from_store` → `_extract_holdings_from_agent_result` 调用点
- **文件(行号)**: `fund_agent/service/extraction.py:1186`
- **输入场景**: `_extract_holdings_from_agent_result` 内部因数据格式异常、列索引解析失败、或任何非预期状态抛出异常（`AttributeError`、`KeyError`、`IndexError` 等）
- **实际分支**: `routed.agent_result.failure is None` → `else` 分支 → `try: holdings = list(_extract_holdings_from_agent_result(...))` → 异常 → `except (DocumentToolError, Exception): pass`
- **预期行为**: 按 AGENTS.md 失败分类要求，`DocumentToolError` 应返回带 `FailureCode` 的 `AnnualHoldingsResult(failure=...)`；`Exception` 应返回 `FailureCode.UNAVAILABLE`
- **实际行为**: 异常被静默吞没，`holdings` 保持空列表 `[]`，继续执行 fallback/继承路径。若所有 fallback 也失败，最终返回 `holdings=(), failure=None`——与"基金确实无股票持仓"不可区分
- **直接证据**:
  - 旧代码 L1176-1186: `except DocumentToolError as exc: return AnnualHoldingsResult(failure=ToolFailure(code=exc.code, message=exc.message))` + `except Exception: return AnnualHoldingsResult(failure=ToolFailure(code=FailureCode.UNAVAILABLE, …))`
  - 新代码 L1183-1186: `except (DocumentToolError, Exception): pass`
  - 同模式在 L1441 (`except DocumentToolError` 改 `pass`)、L1563（QDII scan）重复出现
- **影响**: 真实 bug 导致的抽取失败被伪装成"基金无持仓"，审计管道无法检测，下游报告生成会输出空持仓数据而不报错
- **建议改法和验证点**:
  1. 将 `except (DocumentToolError, Exception): pass` 拆分：`DocumentToolError` → 记录 warning 并继续 fallback；`Exception` → 记录 error 并继续 fallback（不要 `pass`）
  2. 在函数末尾增加：若走了所有 fallback 路径且 `holdings` 仍为空，且 `routed.agent_result.failure` 原本为 None（说明首次 try 抛了异常），则返回带 `FailureCode.UNAVAILABLE` 的 failure
  3. 对 L1441 和 L1563 同理处理
- **修复风险（低）**: 仅增加日志/错误分类，不改变 fallback 逻辑
- **严重程度（高）**: 静默数据丢失，违反项目失败分类硬性要求

### 3-未修复-中-QDII 列索引兜底将 `stock_code` 映射到公司名称

- **入口/函数**: `_holdings_column_indexes`
- **文件(行号)**: `fund_agent/service/extraction.py:4838-4840`
- **输入场景**: QDII 持仓表头缺少"证券代码"列（仅有"公司名称"列）
- **实际分支**: `if "stock_code" not in mapping and "stock_name" in mapping:` → `mapping.setdefault("stock_code", mapping["stock_name"])`
- **预期行为**: `stock_code` 应为证券标识符（如 "AAPL"、"MSFT"）
- **实际行为**: `stock_code` 和 `stock_name` 指向同一列索引，`HoldingExtraction.stock_code` 将包含公司名称（如 "Apple Inc"）而非证券代码
- **直接证据**: L4838-4840 将 `stock_name` 的列索引赋值给 `stock_code`，两字段读取同一列数据
- **影响**: 下游任何依赖 `stock_code` 为真实证券代码的逻辑（如持仓去重、代码查找）将行为异常；`stock_code` 为空字符串或公司名均不可作为证券标识
- **建议改法和验证点**: 当无证券代码列时，`stock_code` 应保持为空字符串，而非复制 `stock_name` 值。`_extract_qdii_holdings_from_tables` 已有 `if not stock_code and not stock_name: continue` 的保护，将 `stock_code` 留空不影响 QDII 路径
- **修复风险（低）**: 删除 L4838-4840 的兜底即可；QDII 表通常有"证券代码"列（L4824 `"证券代码" in cell_clean` 已覆盖）
- **严重程度（中）**: 语义错误，`stock_code` 字段含义被破坏
