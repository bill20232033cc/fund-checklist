## 4. 语义裁决：高分+critical regenerate 耗尽后返回 passed_with_degradation

### 问题

Plan 措辞为「模板降级」。实际实现路径（audit_pipeline.py:2708-2740）：

```python
# 所有修复尝试用完：得分 < 50 返回模板，≥ 50 返回 LLM 内容（标记降级）
final_score = state.current_score or 0
if final_score < 50 or not content:
    # 低分 → 模板降级
    template_content = self._generate_template_chapter(...)
    state.status = "passed_with_degradation"
    ...
    return template_content
else:
    # 中等分数 → 返回 LLM 内容，标记降级
    state.status = "passed_with_degradation"
    state.record_event("passed_with_degradation", {
        "reason": "audit_exhausted_medium_score",
        "final_score": final_score,
    })
    ...
    return content if content else last_valid_content
```

高分+critical 耗尽时走 `else` 分支（final_score >= 50），返回 LLM 内容（非模板内容），状态 `passed_with_degradation`。

### 裁决

**该实现满足 plan 意图，无需改为强制模板降级。** 理由：

1. **状态非 passed**：`passed_with_degradation` ≠ `passed`，满足 plan「状态非 passed」要求。
2. **事件记录 critical 违规**：`record_event("passed_with_degradation", {"reason": "audit_exhausted_medium_score", "final_score": ...})` — 区分于数据不足降级的 `"template_fallback"` 事件。
3. **有界**：`regenerate_attempts == 3`（MAX_REGENERATE_ATTEMPTS），不会死循环。
4. **内容选择合理**：高分章节（>=80）的 LLM 内容虽有 critical 但整体质量高于模板；模板内容更适用于低分（<50）场景。两种降级路径（模板 vs LLM 内容）按分数区分，语义一致。
5. **降级原因可追溯**：`state.record_event` 中 `reason` 字段区分 `"audit_exhausted_low_score"` / `"audit_exhausted_medium_score"` / `"template_fallback"`（数据不足）。

plan「模板降级」措辞为简化表述，实现沿用既有 `audit_exhausted_medium_score` 路径是正确的设计选择。
